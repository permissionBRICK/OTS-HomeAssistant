# v2.1.0 — Discovery, dynamic IP recovery and DHW controls

This release combines [PR #17](https://github.com/permissionBRICK/OTS-HomeAssistant/pull/17)
and [PR #18](https://github.com/permissionBRICK/OTS-HomeAssistant/pull/18).

## Changes

- Adds writable domestic hot-water Comfort, Eco, Reduced and Boost temperature
  controls, using the bindings and limits from the Ochsner Smart app. Controls
  appear only when the heat pump exposes the corresponding values.
- Adds automatic DHCP discovery with one-click adoption and an explicit
  **Add integration → Ochsner Local OTS → Scan network** option.
- Recovers from IP address changes by verifying the saved serial number at the
  new address. Existing entity IDs, device assignments and history are retained.
- Tries the saved MAC's cached DHCP address first. Full subnet scans run only
  when selected from the menu or when the pump is unavailable and quick
  discovery fails. Full recovery scans have a five-minute cooldown.
- Fixes **Failed to unload** for configurations that load only some entity
  platforms.
- Adds automated HACS and Hassfest validation and prepares the repository for
  official HACS listing. Listing itself requires a separate submission.

## Updating through HACS

1. Update **Ochsner Local OTS** to **v2.1.0** in HACS. If testing a feature branch,
   use the integration's **Redownload** option and select **v2.1.0**.
2. Fully restart Home Assistant, especially if the entry previously reported
   **Failed to unload**. Keep the existing integration entry.
3. To add the DHW controls to an existing installation, open the integration's
   **Configure** options and select **Local catalog scan now (accountless; add
   missing entities)**. Existing sensor entities are preserved.

To test discovery without removing the existing heat pump, choose **Add
integration → Ochsner Local OTS → Scan network** and select that pump.
**Already configured** is the expected result; it does not create a duplicate.

Automatic discovery depends on Home Assistant receiving suitable DHCP/network
information. Hostname and MAC vendor patterns are hints; the local API must
confirm the model and serial. Manual scanning remains available when no card
appears. Discovery scans support private IPv4 networks; see the
[README](https://github.com/permissionBRICK/OTS-HomeAssistant#2-add-the-integration-into-home-assistant)
for scope and routing limitations.

## Validation

The combined changes passed **106 tests**, with **21 skipped** because historical
APK/bundle research files were unavailable, using Python 3.14.7 and Home
Assistant 2026.9.1. Tests include real HA registries/coordinators and HTTP
simulation of address changes, quick recovery, serial mismatches and unloading.

Earlier live branch tests on HA 2026.9.0 preserved all 441 existing entity
records. The available pump has no DHW circuit, so actual DHW writes remain
untested on hardware. A real router lease change and the first-install
automatic discovery card also remain acceptance tests.
